# Capability-Derived Candidate Grammar

This grammar is the first implementation of the issue-ID-free search space required by the paper execution plan. It is generated by `CapabilityCandidateGrammar` from `BranchCapabilityProfile`; no historical issue number, bug reproducer, or backend-specific failure string participates in candidate construction.

## Candidate classes

The common writable prefix contains:

```text
read, insert, update, delete-row,
alter-schema, create-index, drop-index,
create-generated-identity, advance-allocator,
create-dependent-object
```

Declared capabilities add only the relevant classes:

| Capability | Added candidates |
|---|---|
| Historical fork | drop/recreate same name, rename/recreate, nested historical branch, historical diff |
| Two or more equivalent observers | alternate observer |
| Branch delete | delete branch, detach, branch again after delete |
| Restart/recovery | restart, retry after restart |

Each candidate carries a source mutation, continuation, trace operation class, and semantic class flags (`identity`, `allocator`, `dependency`, `lifecycle`, `recovery`, `observer`, or `ordinary`). Unsupported candidates are not emitted.

## Fair ordering protocol

- **Uniform:** seeded Fisher–Yates permutation of the complete generated candidate set.
- **Guided:** the same candidate set, seeded tie-breaking, ordered by semantic priority: identity, allocator, dependency, lifecycle, recovery, observer, ordinary.
- The candidate-set SHA-256 fingerprint is computed from canonical candidate descriptors and is independent of observer declaration order.
- A fair comparison must use identical candidate sets, seed sets, trace-length limits, timeout, and backend capability profile. Only ordering may differ.

## Current test gate

`CapabilityCandidateGrammarTests` verifies capability gating, absence of issue identifiers, seeded permutation stability, guided ordering, and fingerprint stability. The grammar is ready for external backend execution once Docker, Rust/Cargo, and pinned Dolt binaries are provisioned. Until then, local tests are harness validation rather than live-system evidence.
